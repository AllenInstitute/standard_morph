Architecture Overview · Standard Morph

Quality control for neuron reconstructions, rebuilt as a modular engine.

The overhaul replaces a single monolithic validator with a context-aware, two-phase QC engine behind one entrypoint — run_qc(). This is the design and the reasoning behind it.

The organizing idea: a QC tool should report what's wrong, not crash on it. A malformed SWC and a clean one flow through the same path and produce the same shape of report — one just names the failure and marks the un-runnable checks skipped.

The shift

From one class to a composable framework

The old workflow still works — but the internals gained structure, context-awareness, and provenance.

Before · Standardizer
  • Thresholds passed as constructor arguments
  • One fixed validate() sequence for every cell
  • No notion of coordinate space or when a check applies
  • Results as loose dicts — hard to trend or store
  • A malformed file threw an exception
After · run_qc
  • Versioned threshold policies, recorded in each report
  • Suites and applicability decide what runs, in what order
  • Coordinate space drives which checks are valid
  • A structured, JSON-ready RunReport
  • A malformed file yields a clean report, never a crash

Core concepts

Five moving parts

ContextQCContext
Runtime metadata: coordinate space, morphology_kind, external resources, ccf_resolution, and policy_version. The user supplies the space; the pre-/post-registration stage is derived, never entered by hand.
MetricMetric
One QC check. Declares its applicability (spaces / kinds / resources), its phase, and — where relevant — its failure scope or topology need. Implements evaluate(...) → MetricResult. Self-registers on import.
Suitedefault_pre / post
A named, ordered list of metrics, mapped to the two coordinate spaces. Applicability is still enforced per-metric, so a mismatched suite fails fast rather than silently skipping.
Policypolicy_v1
A versioned threshold dictionary. Metrics read thresholds from the policy, never the call site; the version is recorded in every report, so results stay reproducible and traceable.
Run reportRunReport
The structured output: two result lists, a summary, and provenance. Every failing metric returns its full flagged-node list, and every summarisable metric a single headline value for trending.

Design decisions

Six choices, and why

01

Array-backed, not a graph object

The morphology is contiguous-indexed numpy arrays (parent, xyz, compartment) with derived adjacency and cached segments.

Why: an SWC is a one-parent-per-node forest — the topology is one int per node. Reindexing gives O(1) lookups and vectorized geometry. networkx is too slow and memory-heavy at fMOST scale (10⁵–10⁶ nodes).
02

Two phases

Integrity metrics read the raw table before a graph is built; quality metrics read the built PreparedMorphology.

Why: two different kinds of "wrong" — a malformed table vs. a malformed neuron. You can't run graph checks on a graph you couldn't build, but you shouldn't crash either.
03

Scoped blocking

Each integrity failure carries a scope — BUILD or TOPOLOGY — matched against each metric's requires_topology.

Why: a duplicate id corrupts topology but not coordinates, so the fraction of nodes outside the CCF mesh is still computable. What broke, matched to what a metric needs, decides exactly what can still run.
04

Applicability & fail-fast

Every metric declares its valid spaces, kinds, and resources; an incompatible request halts before any work.

Why: a post-registration check should never silently no-op on an image-space cell. Failing loudly beats a report that quietly omits a check.
05

Versioned policies

Thresholds live in versioned definitions, recorded in every report; changing one means a version bump.

Why: "what threshold produced this result?" must be answerable from the report alone, and threshold changes must be traceable and governed.
06

One scalar per metric

Every summarisable metric sets value + value_label — a max, count, or fraction. Binary checks leave it None.

Why: a QC portal wants one sortable, trendable column per check across thousands of cells. Full detail stays in measurements.
